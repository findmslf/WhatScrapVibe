Poste le 13 Oct 2026 · #1 - C'est quoi le web scraping ?

Le web scraping (ou "grattage" de donnees), c'est le fait de recuperer automatiquement des informations affichees sur des pages web, au lieu de les copier-coller a la main. Un programme visite la page, lit le code, et en extrait ce qui t'interesse : titres, prix, liens, images, avis...

A quoi ca sert ?

  • Comparer des prix sur plusieurs boutiques
  • Recuperer des annonces, des offres d'emploi, des articles
  • Constituer une base de donnees pour une analyse / un projet
  • Surveiller un changement (un stock, une dispo, une note)

Le vocabulaire a connaitre

  • HTML : le code qui compose la page (le "texte brut" avec des balises).
  • Parser : analyser ce code pour y retrouver des morceaux precis.
  • Selecteur : l'adresse qui designe un element dans la page (voir #3).
  • Requete (request) : quand ton programme demande la page au serveur.
  • Crawler : un scraper qui suit les liens pour visiter plein de pages.
Scraping ≠ API. Une API, c'est une porte officielle fournie par le site pour recuperer ses donnees proprement. Si elle existe, prefere-la toujours au scraping : c'est plus stable, plus rapide, et autorise.

Poste le 13 Oct 2026 · #2 - Comment marche une page web

Pour gratter, il faut comprendre de quoi est faite une page. Une page web = du HTML : du texte organise avec des balises entre chevrons.

<div class="produit">
  <h2 class="titre">T-shirt rouge</h2>
  <span class="prix">19,90 €</span>
  <a href="/produit/42">Voir</a>
</div>

Ce qu'il faut retenir

  • Une balise a un nom (div, h2, a, img, span...).
  • Elle peut avoir une classe (class="prix") : une etiquette que le scraper adore, parce qu'elle vise pile le bon element.
  • Elle peut avoir un id (id="header") : unique dans la page.
  • Elle a souvent des attributs : un lien a href, une image a src.
  • Les balises sont imbriquees : un bloc produit contient un titre, un prix, etc. C'est ce qui permet de dire "le prix DANS ce produit".

Le CSS, lui, sert a la mise en forme (couleurs, tailles). Nous, ce qui nous interesse, ce sont surtout les classes et la structure, parce qu'on va s'en servir comme reperes.

Poste le 13 Oct 2026 · #3 - Trouver les bons selecteurs CSS

Un selecteur CSS, c'est l'adresse qui designe un (ou plusieurs) element(s). C'est LE truc a maitriser. Les plus utiles :

  • h2 — toutes les balises h2
  • .prix — tout ce qui a la classe prix (le point = classe)
  • #header — l'element avec l'id header (le diese = id)
  • .produit .titre — un .titre situe a l'interieur d'un .produit
  • a + attribut href — pour choper l'URL d'un lien
  • img + attribut src — pour choper l'adresse d'une image

Comment les trouver sur un vrai site

  1. Sur la page, clic droit sur l'element qui t'interesse → Inspecter (Inspect).
  2. Le code s'ouvre et surligne ta balise. Repere son nom et sa classe.
  3. Astuce : clic droit sur la balise dans l'inspecteur → Copier → Copier le selecteur.
Flemme ? Dans l'outil, en Mode avance, clique sur "Trombonne, remplis les cases pour moi" : j'analyse la page et je te propose les selecteurs tout seul. Tu verifies, tu ajustes, tu lances.
Regle d'or : prefere une classe parlante (.price, .product-title) plutot qu'un truc fragile. Si le selecteur est trop precis (genre div > div > div:nth-child(3)), il cassera au moindre changement du site.

Poste le 13 Oct 2026 · #4 - Statique vs dynamique (le Mode JS)

Il y a deux grandes familles de pages :

Les pages statiques

Le contenu est deja dans le HTML quand la page arrive. C'est le plus simple et le plus rapide a scraper. La plupart des blogs, des articles, des vieux sites.

Les pages dynamiques (JavaScript)

Le HTML arrive presque vide, puis du JavaScript charge le contenu apres coup (sites en React/Vue, scroll infini, boutons "charger plus"). Si tu scrapes ca en mode normal, tu recuperes... rien, ou du vide.

La solution : coche "Mode JS (site dynamique)" dans l'outil. Ca ouvre un vrai navigateur en coulisse (Playwright), qui laisse le JavaScript s'executer avant de lire la page. C'est plus lent, mais ca chope le contenu.

Comment savoir laquelle c'est ?

Simple : tu scrapes en mode normal. Si tu as 0 resultat alors que tu vois bien le contenu dans ton navigateur → c'est surement du dynamique, active le Mode JS et relance.

Poste le 13 Oct 2026 · #5 - Scraper proprement et dans les regles

Le scraping, c'est puissant, mais ca se fait avec la tete. Un bon scrapeur est discret et respectueux. Les regles de base :

1. Le fichier robots.txt

Beaucoup de sites ont un fichier robots.txt (ex : exemple.com/robots.txt) qui dit ce que les robots ont le droit de visiter. Respecte-le. L'outil le verifie pour toi quand l'option est cochee.

2. Les conditions d'utilisation (CGU)

Certains sites interdisent explicitement le scraping dans leurs CGU. Lis-les. Et si un site met un anti-bot (Cloudflare, captcha), c'est qu'il dit clairement non : on insiste pas.

3. Les donnees personnelles (RGPD)

Attention : recuperer des donnees personnelles (noms, emails, photos de gens...) est encadre par la loi (RGPD en Europe). Dans le doute, on ne collecte pas de donnees perso.

4. La politesse technique

  • Ne bombarde pas le serveur : mets un delai entre les requetes.
  • Scrape aux heures creuses si tu fais du volume.
  • Ne te fais pas passer pour quelqu'un d'autre, ne surcharge pas le site.
La boussole : si le site a une API, utilise-la. Si t'as un doute, demande l'autorisation. Scrape ce qui est public et que t'as le droit de prendre.

Poste le 13 Oct 2026 · #6 - Les outils du metier

Pour commencer : ce site

Tu es au bon endroit. L'outil fait le scraping sans code : URL, cases a cocher ou selecteurs, export CSV/Excel/JSON. Parfait pour apprendre les concepts sans te prendre la tete.

L'etape d'apres : Python

Quand tu voudras aller plus loin, le duo de base c'est requests (telecharger la page) + BeautifulSoup (la parser) :

import requests
from bs4 import BeautifulSoup

html = requests.get("https://quotes.toscrape.com").text
soup = BeautifulSoup(html, "html.parser")

for c in soup.select(".quote"):
    texte = c.select_one(".text").get_text()
    auteur = c.select_one(".author").get_text()
    print(auteur, ":", texte)

Les autres outils

  • Scrapy : un framework complet pour crawler plein de pages, gerer la pagination, exporter. Pour les gros projets.
  • Playwright / Selenium : pilotent un vrai navigateur, indispensables pour le JavaScript (c'est ce que l'outil utilise en Mode JS).
  • lxml : un parser tres rapide, souvent utilise avec BeautifulSoup.
Conseil : commence simple (requests + BeautifulSoup sur un site statique). Passe aux navigateurs automatises seulement quand c'est vraiment necessaire.

Poste le 13 Oct 2026 · #7 - S'entrainer pour de vrai

Le scraping, ca s'apprend en pratiquant. Et surtout : entraine-toi sur des sites faits pour ca, histoire de pas deranger de vrais sites.

Les terrains d'entrainement (100% autorises)

  • quotes.toscrape.com — des citations. Parfait pour debuter (statique + une version JS).
  • books.toscrape.com — une fausse librairie avec prix, notes, pagination. Le classique.
  • scrapethissite.com — des exercices progressifs (formulaires, pagination, AJAX).
  • webscraper.io/test-sites — des sites de test e-commerce.

Un parcours d'apprentissage

  1. Avec cet outil : scrape les citations de quotes.toscrape.com (mode simple).
  2. Passe en mode avance : recupere citation + auteur separement (conteneur .quote).
  3. Teste l'auto-parser sur books.toscrape.com et compare avec ce que t'aurais fait a la main.
  4. Refais la meme chose en Python (requests + BeautifulSoup, voir #6).
  5. Apprends la pagination : suivre les liens "page suivante" pour tout recuperer.
  6. Attaque un vrai site simple et autorise, avec delai entre les requetes.
Mantra du debutant : un petit scrape qui marche > un gros projet qui plante. Avance par petites etapes.

Poste le 13 Oct 2026 · #8 - Les galeres classiques du debutant

"J'ai 0 resultat alors que je vois le contenu"

→ Le site est surement dynamique (JavaScript). Coche le Mode JS et relance. Verifie aussi ton selecteur (voir ci-dessous).

"Je recupere un truc bizarre : 'verification de securite'..."

→ Le site est protege par un anti-bot (Cloudflare, captcha). Tu recois la page de blocage, pas le contenu. L'outil te previent maintenant. Ce site ne veut pas etre scrape : on passe a autre chose.

"Mon selecteur ne ramene rien / pas la bonne chose"

  • Verifie que la classe existe bien (clic droit → Inspecter).
  • Attention aux fautes : .titre et .Titre, c'est pas pareil.
  • Un point pour une classe, un diese pour un id. Pas d'espace en trop.

"Les liens/images sont incomplets (commencent par /...)"

→ Ce sont des liens relatifs. Pas de panique : l'outil les transforme automatiquement en liens complets.

"Ca marchait hier, plus aujourd'hui"

→ Le site a change son code. C'est la vie du scrapeur : il faut re-verifier les selecteurs de temps en temps. Plus ton selecteur est simple, moins ca casse.

Bloque ? Reviens sur l'outil et demande-moi dans la Tchatche : tape ta question (selecteur, mode JS, export...) et je t'aiguille. Ou lance le tuto.

Poste le 13 Oct 2026 · #9 - Veille automatisee sur TikTok

Pourquoi tu peux pas juste le scraper

TikTok charge tout en JavaScript derriere un mur de connexion, avec une detection anti-bot muscle. Et leurs conditions d'utilisation interdisent la collecte automatisee non autorisee. Resultat : scraper maison = blocages permanents + risque juridique. On passe par l'officiel.

La voie officielle : les API TikTok

Sur developers.tiktok.com :

  • Research API — concue pour la veille/recherche : videos et commentaires publics, recherche par mots-cles, hashtags, dates. Reservee aux chercheurs / organisations approuves (demande a faire, dispo surtout UE & US).
  • Display API — afficher les contenus d'un compte qui t'a donne son accord (OAuth). Parfait pour suivre tes propres comptes.
  • Business / Marketing API — stats des comptes pro et des campagnes pub.
  • Commercial Content API — bibliotheque publique des publicites.

Les outils de veille tout faits (sans coder)

Des plateformes payantes mais conformes, qui font la veille TikTok pour toi : Exolyt, Pentos, Analisa.io, Brand24, Talkwalker, Hootsuite. Tu entres tes mots-cles / comptes, elles te sortent les stats et les alertes.

Automatiser proprement

  • Demande l'acces a l'API qui correspond a ton besoin, recupere tes cles.
  • Ecris un petit script (Python) qui interroge l'API et stocke les resultats.
  • Planifie-le avec un cron (ex : tous les matins) + une alerte email/Discord.
En resume : la veille TikTok, c'est API officielle ou outil dedie. Jamais de scraping sauvage de l'app.

Poste le 13 Oct 2026 · #10 - Veille automatisee sur Twitter / X

Pourquoi tu peux pas juste le scraper

X a serieusement verrouille ces dernieres annees : affichage derriere connexion, anti-bot, CGU qui interdisent le scraping, et les miroirs type Nitter sont quasi tous morts. Le scraping d'X, aujourd'hui, c'est la galere assuree et c'est contre les regles.

La voie officielle : l'API X v2

Sur developer.x.com. Attention, l'acces est devenu payant et etage :

  • Free — tres limite (surtout pour publier, lecture quasi nulle).
  • Basic — payant (~100$/mois), quotas de lecture modestes.
  • Pro / Enterprise — pour du volume serieux (cher).

Les briques utiles pour la veille : recent search (chercher les tweets recents sur des mots-cles) et filtered stream (flux temps reel avec des regles de filtrage).

Les outils de veille tout faits (sans coder)

Du social listening cle en main : Brandwatch, Talkwalker, Meltwater, Mention, Brand24, Hootsuite, Sprout Social, et X Pro (ex-TweetDeck). Tu definis tes mots-cles/comptes, tu recois tableaux de bord et alertes.

Automatiser proprement

  • Cree un compte developpeur X, choisis le palier adapte, recupere ton Bearer Token.
  • Script Python qui appelle recent search (ou ouvre un filtered stream) et enregistre les tweets.
  • Cron + alerte. Respecte les quotas (rate limits) pour pas te faire couper.
RGPD : les tweets contiennent des donnees personnelles. Si tu stockes/analyses, respecte le cadre legal (surtout en Europe).
